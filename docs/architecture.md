## 2. Security & Data Isolation Model

1. **Authentication:**
   - Handled via Supabase Auth with email/password.
   - Profile automatically synced to `public.profiles` using a PostgreSQL trigger.
   - JWT tokens generated by Supabase are passed in the `Authorization: Bearer <token>` header to the FastAPI backend.

2. **Authorization & Backend Security:**
   - FastAPI dependency `get_current_user` extracts and cryptographically verifies the token against Supabase.
   - User identity (`user_id`) is strictly extracted from the verified token payload.
   - CRUD operations reject cross-tenant data requests with HTTP 403 / 404.

3. **Database Row Level Security (RLS):**
   - RLS is enabled on all tables.
   - Even direct client-to-Supabase queries are protected by `auth.uid() = user_id` policies.

## 3. Future Stage 2 AI Agent Architecture (Roadmap)

In Stage 2, the backend will incorporate LangGraph multi-agent workflows without altering the existing database or API contracts.

### Planned Directory Layout:
```
backend/app/
├── agents/
│   ├── requirement_agent.py    # Extracts constraints, budget distribution, passenger profiles
│   ├── destination_agent.py    # Analyzes destination attractions, distances, seasonality
│   ├── weather_agent.py        # Real-time forecast & climate risk assessment
│   ├── itinerary_agent.py      # Generates day-by-day dynamic schedule
│   ├── adaptation_agent.py     # Adjusts plan based on delays, preferences, or disruptions
│   └── validator.py            # Verifies feasibility, budget constraints, timing
│
├── graph/
│   ├── state.py                # LangGraph TravelState TypedDict
│   └── travel_graph.py         # StateGraph orchestration & conditional routing
│
└── tools/
    ├── weather.py              # Weather API integration tool
    ├── places.py               # Google Places / OpenStreetMap tool
    ├── routing.py              # Route optimization & transit duration tool
    └── fuel.py                 # Fuel / Tolls / Transit cost estimator tool
```
